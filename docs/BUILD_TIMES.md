読み取れること:

- Phase 0 と Phase 1 で、1回ずつの計測では「変更なし」自体が 2.5〜5.2 秒の幅でぶれた。クリーンも 17〜32 秒とぶれており、Phase 1 の方が速いのはコードではなく実行環境の差。1回の計測で良し悪しを判断しない（以降は3回の中央値を取る）。
- アプリのコードが同じでも、クリーンビルドは Xcode 16.4 で 17.14 秒（6b4f857）と 44.09 秒（7d3d8c5）だった。CI のクリーンビルドはランナーの状態で大きく変わるので、比較には使わない。
- 3回の中央値では、View 1ファイル変更は約 3 秒（3.03 / 3.17）で、「変更なし」（2.17〜3.15）との差は 1 秒未満。Core 型のインターフェース変更は 3.1〜4.6 秒。
- Phase 1（アプリ本体の Swift 2,107 行、47 ファイル: Core 25 / UI 22）でも、View 1ファイル変更の増分ビルドは「変更なし」との差が 1 秒未満だった。Swift のコンパイル自体より xcodebuild の固定分が大きい。
- 型チェックが 100ms を超えた関数・式は 0 件。
- Phase 2（アプリ本体の Swift 3,771 行、74 ファイル: Core 43 / UI 31）では、View 1ファイル変更が Xcode 16.4 で 2.37 秒、26.3 で 4.93 秒だった。
  同じコードでランナーによって 2 倍ほど違い、「変更なし」（1.41 / 3.12 秒）との差はどちらも 1〜2 秒。コード量が 1.8 倍になっても、1ファイルの変更で再コンパイルされる範囲は増えていない。
- Phase 4（アプリ本体の Swift 8,615 行、123 ファイル: Core 68 / UI 55）では、View 1ファイル変更が 4.55 / 3.67 秒、「変更なし」との差は 1.8〜2.0 秒。
  Core 型のインターフェース変更は 6.0〜6.9 秒で、Phase 2 より 1〜3 秒長い（Core の型を参照する View が増えたため）。
- Phase 5（アプリ本体の Swift 12,456 行、160 ファイル: Core 95 / UI 65）では、Xcode 16.4 の View 1ファイル変更は 2.20 秒（「変更なし」との差 1.2 秒）。
  一方 Xcode 26.3 は 6.30 秒（差 3.7 秒）で、Phase 4 の 3.67 秒から延びた。3回の幅は小さい（6.21–6.63）ので、ランナーのぶれではなさそう。
  原因（Xcode 26 のビルドの仕組みか、ファイル数の増加か）は Phase 8 で調べる。
- Phase 6（アプリ本体の Swift 12,857 行、165 ファイル: Core 97 / UI 68）では、Xcode 26.3 の View 1ファイル変更が 4.15 秒（「変更なし」との差 2.3 秒）に戻った。
  変更対象のファイル（`PageIndicatorView.swift`）は Phase 5 と同じで、コードは 5 ファイル増えただけ。Phase 5 の 6.30 秒は、3回の幅が小さくても、
  ランナーの差だった可能性が高い（同じ CI の中の3回は同じランナーで動くので、ランナーの差は幅に表れない）。Phase 8 では複数回の CI で比べる。
- Phase 6 で増えた Foundation Models のコードは、Xcode 16.4（iOS 18 SDK）では `#if canImport` で外れ、Xcode 26.3（iOS 26 SDK）ではコンパイルされる。
  どちらでも 100ms を超える型チェックはなかった。
