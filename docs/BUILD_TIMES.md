## macOS（GitHub Actions `macos-15`、Apple M1 仮想 3 コア、iOS Simulator「iPad (10th generation)」向け Debug ビルド）

単位は秒。「クリーン」はパッケージ解決を含む。`xcodebuild` は変更がなくても数秒かかるため、増分ビルドの値には常にその固定分が含まれる。

| 日付 | コミット | Xcode（Swift） | 回数 | クリーン | 変更なし | View 1ファイル変更 | Core 型の変更 | 遅い型チェック（100ms 超） |
|---|---|---|---|---|---|---|---|---|
| 10-29 | e083d50（Phase 0） | 16.4（6.1.2） | 各1回 | 25.04 | 2.80 | 1.98 ※1 | 2.18 ※1 | 未取得 ※2 |
| 10-29 | e083d50（Phase 0） | 26.3（6.2.4） | 各1回 | 31.62 | 5.18 | 2.96 ※1 | 4.15 ※1 | 未取得 ※2 |
| 10-29 | 6b4f857（Phase 1） | 16.4（6.1.2） | 各1回 | 17.14 | 4.42 | 3.26 | 2.59 | 0 件 |
| 10-29 | 6b4f857（Phase 1） | 26.3（6.2.4） | 各1回 | 17.46 | 2.47 | 3.02 | 3.62 | 0 件 |

※1 Phase 0 は View が1ファイルしかないため、変更対象が Phase 1 と異なる（Phase 0: `MyHomeApp.swift` と `AppInfo`、Phase 1: `PageIndicatorView.swift` と `HomeItem`）。
※2 計測スクリプトの不具合（サマリー出力で停止）で一覧を出せなかった。修正済み。

読み取れること:

- Phase 0 と Phase 1 で、1回ずつの計測では「変更なし」自体が 2.5〜5.2 秒の幅でぶれた。クリーンも 17〜32 秒とぶれており、Phase 1 の方が速いのはコードではなく実行環境の差。1回の計測で良し悪しを判断しない（以降は3回の中央値を取る）。
- Phase 1（アプリ本体の Swift 2,107 行、47 ファイル: Core 25 / UI 22）でも、View 1ファイル変更の増分ビルドは「変更なし」との差が 1 秒未満だった。Swift のコンパイル自体より xcodebuild の固定分が大きい。
- 型チェックが 100ms を超えた関数・式は 0 件。

## Linux（Core のみ、`scripts/measure-core-build.sh`）

環境: この作業環境の Linux VM（x86_64、4 コア、メモリ 15GB）。単位は秒。3回計測の中央値（括弧内は最小–最大）。
「変更なし再ビルド」はほぼ SwiftPM 自体の処理時間で、コード量にはほとんど依存しない。
